# Contributing

Contributions to documentation are welcome!

## Guidelines

1. Focus on public-facing integration content
2. Do not add private architecture details
3. Update examples when APIs change
4. Clearly mark planned vs implemented features
5. Include code examples where appropriate

## Process

1. Fork this repository
2. Create a feature branch
3. Make your changes
4. Open PR with description
5. Wait for maintainer review

## Public Boundary

Keep all content suitable for public consumption.

Private architecture documentation belongs in mwz-docs (private).
